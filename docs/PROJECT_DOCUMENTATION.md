# Project Documentation

## Architecture

```text
Signed-in LEB2 browser session
        │
        ▼
Manifest V3 extension
  ├─ discovers active classes
  ├─ identifies the signed-in LEB2 account
  ├─ checks teaching-team roles
  ├─ fetches assessment activities
  └─ creates normalized Task payloads
        │ HTTP on 127.0.0.1:8765
        ▼
Local Python companion
  ├─ validates the generated shared secret
  ├─ refreshes the user's Google OAuth token
  ├─ compares existing Tasks
  └─ creates/patches Google Tasks
        │
        ▼
Google Tasks API
```

Chrome and Brave use the same localhost companion. Google refresh tokens stay outside the extension.

## Components

| File | Purpose |
|---|---|
| `extension/manifest.json` | Manifest V3 permissions, stable unpacked identity, popup, service worker |
| `extension/background.js` | Browser alarms, LEB2 extraction, role filtering, sync orchestration |
| `extension/lib.js` | Pure task/date/role helpers |
| `extension/popup.*` | User controls and status |
| `companion.py` | Loopback API and Google Tasks client |
| `setup.py` | Generates per-installation secret/config and Windows Startup entry |
| `oauth_setup.py` | Google OAuth PKCE and token exchange |
| `oauth_listener.py` | One-request loopback OAuth callback |
| `scripts/doctor.py` | Local installation diagnostics |
| `scripts/package_release.py` | Builds a public-safe source archive |
| `scripts/secret_scan.py` | Rejects known private files and credential patterns |

## LEB2 extraction

The extension opens `https://app.leb2.org/class` in an inactive tab and executes a MAIN-world script so requests use the user's existing authenticated browser session. It does not export browser cookies.

Class cards are read from `.class-card[data-url]`. The extension derives the current internal user identifier from an authenticated activity page, checks `/class/{id}/member/instructor`, and excludes teaching roles.

Assessments are read from LEB2's internal student assessment endpoint. Only required fields are returned from the page context:

- activity and class IDs;
- title;
- start/due dates;
- submission ID/time/late state.

Internal endpoints and selectors are unstable because this is not an official LEB2 API.

## Google Task model

Task title:

```text
[LEB2] COURSE_CODE — ASSIGNMENT_TITLE
```

Task notes include course information, status, a direct LEB2 link, and a stable marker:

```text
[LEB2_ACTIVITY_ID:12345]
```

The companion uses the marker to find an existing Task. It creates a missing Task, patches a changed Task, and skips an identical Task. Completed Tasks are included in matching so a second sync does not duplicate submitted work.

Google Tasks treats due values as dates. Exact LEB2 due time is not represented.

## Scheduling

- Default interval: 30 minutes.
- Valid range: 0.5–168 hours in 0.5-hour increments.
- `chrome.runtime.onStartup`: schedules the alarm and triggers a sync.
- `chrome.alarms`: triggers repeating sync while the browser can run the service worker.
- `chrome.storage.local`: stores interval, last result, timestamp, and last error.

## Local companion security

- Binds only to `127.0.0.1:8765`.
- Allows CORS only for the stable unpacked extension ID.
- Requires a random `X-LEB2-Secret` generated by `setup.py`.
- Reads the same secret from ignored local configuration.
- Stores Google OAuth files in the project folder; Git ignores them.
- Does not receive an LEB2 password or raw browser cookie.

Local users control their own machines and source copies. The companion is a local safety boundary, not DRM or remote licensing.

## OAuth

The public beta uses a per-user Google Desktop OAuth client. The requested scope is:

```text
https://www.googleapis.com/auth/tasks
```

The user's refresh token is stored in `google_token.json`. The extension never receives it. See `docs/GOOGLE_OAUTH_SETUP.md`.

## Testing

```bash
node tests/lib.test.js
python -m unittest tests.test_companion -v
node --check extension/background.js
node --check extension/lib.js
node --check extension/popup.js
python -m py_compile companion.py oauth_setup.py oauth_listener.py setup.py
python scripts/secret_scan.py
```

CI performs the same syntax, unit, and secret-safety checks on pushes and pull requests.

## Release process

1. Ensure generated/private files are ignored.
2. Run all tests.
3. Run `python scripts/secret_scan.py`.
4. Run `python scripts/package_release.py`.
5. Inspect `dist/LEB2-Tasks-Sync-vX.Y.Z.zip`.
6. Create a GitHub release and attach that archive.

The release archive contains templates, not generated runtime credentials.

## Maintenance

If LEB2 changes:

1. Reproduce the failure while signed in.
2. Inspect current page selectors and network requests.
3. Update pure helper tests first where possible.
4. Minimize returned data.
5. Verify one real create and one idempotent repeat sync.
6. Never log cookies, tokens, full member lists, or unrelated student records.
